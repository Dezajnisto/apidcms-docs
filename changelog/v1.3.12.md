<h3>Many-to-many связи (M:M)</h3>
<p>Добавлена поддержка связей «многие-ко-многим» через универсальную pivot-таблицу <code>entity_relations</code>. Одна запись может относиться к нескольким категориям одновременно.</p>

<h4>Что нового</h4>
<ul>
<li><strong>Pivot-таблица:</strong> <code>entity_relations(source_table, source_id, relation_name, target_id)</code> — одна таблица для всех M:M-связей</li>
<li><strong>Конфигурация:</strong> добавлен тип <code>"type": "many-to-many"</code> в <code>page_config.relations</code></li>
<li><strong>Админка:</strong> multi-select чекбоксы с деревом (отступы для подкатегорий) и поиском</li>
<li><strong>Сохранение:</strong> автоматическое управление pivot-записями при create/update/delete</li>
<li><strong>Фронтенд:</strong> Twig-функция <code>get_pivot(source_table, source_id, relation_name, target_table)</code></li>
<li><strong>Фильтрация:</strong> <code>get_filters</code> с pivot-aware фильтрацией через subquery</li>
<li><strong>Счётчики категорий:</strong> sidebar считает через entity_relations (M:M-aware)</li>
<li><strong>Обратная совместимость:</strong> 1:M связи работают как раньше, M:M включается явно</li>
</ul>

<h4>Исправления</h4>
<ul>
<li>Удаление записей автоматически чистит pivot-связи (entity_relations)</li>
<li>Сброшен старый хардкод poetry_category — заменён на универсальную очистку</li>
<li>M:M поля рендерятся отдельно от цикла структуры таблицы (виртуальные, не колонки БД)</li>
</ul>

<h4>Пример конфигурации</h4>
<pre><code>{
  "relations": {
    "categories": {
      "table": "categories",
      "label": "name",
      "value": "id",
      "type": "many-to-many",
      "tree": true,
      "search": true
    }
  },
  "get_filters": {
    "categories": "categories"
  }
}</code></pre>
