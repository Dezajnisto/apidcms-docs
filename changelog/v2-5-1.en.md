# v2.5.1 — DEFAULT in the schema: a value, not SQL text

**Date:** November 16, 2026
**Type:** fix

## What was wrong

`PRAGMA table_info` returns the default not as a value but as **SQL text**: for a
string column the quotes stay inside — `'active'`, `"active"`, `` `active` ``,
`[active]`.

Two problems followed:

1. **The quotes leaked into the JSON Schema.** `GET /api/v1/tables/{table}/json-schema`
   and the `schema.get` MCP tool reported `"default": "'active'"`. An agent reads
   the schema to learn what it may omit — and, trusting it, would have written
   the value **together with the quotes**.
2. **Dropping a column corrupted the default.** SQLite has no `DROP COLUMN`, so
   the table is rebuilt: the old default text was quoted a second time and became
   `DEFAULT '''active'''`.

Found right after rolling 2.5.0 out to bajto.ru — on the very first schema request
for the live `catalog` table.

## What changed

`Core\Database::normalizeDefault()` — one shared normalisation for both the schema
and the table rebuild:

- a string literal is unwrapped into a value (all four quote styles, including a
  doubled quote inside);
- expressions (`CURRENT_TIMESTAMP`, `NULL`) and numbers are left alone.

`SchemaInspector` uses it when building the schema, `deleteColumn()` when creating
the new table (numbers are no longer quoted).

## How to check

```
GET /api/v1/tables/pages/json-schema
→ "status": { "type": "string", "default": "active" }
```

Before: `"default": "'active'"`.

## Compatibility

No breaking changes. Only what an agent sees in the schema changes — and it
changes towards the truth.
