# v2.4.0 — API, которому можно доверить запись

**Дата:** 16 ноября 2026
**Тип:** feature

## Зачем

CMS сегодня нужна не только человеку в браузере: контент всё чаще правит агент.
Агенту нужны три вещи — узнать, как устроен проект, понять, что значат данные, и
суметь безопасно что-то записать. Всё три появились в этом релизе.

Главная проблема была не в нехватке эндпоинтов, а в **молчаливой неполноте**:
`/api/v1/tables` отвечал `200 OK` с формой таблиц, а смысл (`price` — это рубли, а
`status` — `active`, а не `published`) и граф страниц оставались за кадром. Запись
принимала что угодно и падала `500` уже внутри базы. Агент строил план на
неполной картине и не замечал этого. `404` дешёвый: его видно и он приводит к
вопросу. Уверенный `200` с половиной правды — дорогой.

## Обнаружение: что это за сайт

**`GET /api/v1`** — публичный индекс: CMS, версия, статус `preview` и список
возможностей, каждая помечена `ready` или `planned`. Заголовок
`X-apidcms-api: v1-preview` есть на всех ответах API.

**`GET /api/v1/schema`** — весь проект одним ответом: таблицы, колонки (тип,
`NOT NULL`, default, enum из `CHECK`), метаданные, внешние ключи, связи
many-to-many и граф страниц. Один запрос вместо обхода `/tables` и `/schema` по
каждой таблице.

**`GET /api/v1/navigation`** — `page_config` (`source_table`, `template`,
`filters`, `get_filters`, `items_per_page`, `sort`) отдаётся разобранным, а не
сырой JSON-строкой. Битый `page_config` не роняет ответ: страница попадает в
список с полем `page_config_error`.

**`GET /api/v1/relations`** — связи many-to-many из `entity_relations`.

## Смысл: чего не знает PRAGMA

Таблица теперь описывается по-человечески: название, назначение, описание; у
колонки — подпись, пояснение, формат, пример и список допустимых значений.
Правится в админке: Таблицы → Структура → **«Семантика»**. Хранится в
`table_meta` и `field_meta`, отдаётся через API: это единственная часть описания,
которую нельзя восстановить из кода.

`null` в `/schema` значит «не описано», а не «не важно» — значения не
выдумываются.

## Запись: проверка вместо мусора в базе

**`GET /api/v1/tables/{t}/json-schema`** — JSON Schema таблицы (draft 2020-12) с
расширениями: подписи, форматы, enum, ссылки на связанные таблицы. Агент валидирует
у себя до отправки.

**`POST`/`PUT` проверяются** по типу колонки, `NOT NULL`, значению по умолчанию,
enum, внешним ключам, формату (`integer`, `money`, `date`, `url`, `email`, `slug`),
длине `VARCHAR(n)`. Незнакомое поле — ошибка, а не тихое отбрасывание: опечатка в
имени поля больше не теряет данные.

Отказ — `422` с машинночитаемым списком, и агент исправляется сам:

```json
{"error": {"code": "validation_failed", "action": "insert",
  "fields": [{"column": "price", "rule": "type",
              "got": "1500 руб", "expected": "integer (INTEGER)"}]}}
```

**`?dry_run=1`** на `POST`/`PUT`/`DELETE` — что изменится и какие страницы это
показывают (`affected_urls` из `page_config`), база не меняется.

**`Idempotency-Key`** — повтор запроса возвращает первый ответ и не создаёт вторую
запись. Агенты ретраят; три одинаковые новости в проде — вопрос времени.

**`GET /api/v1/audit`** — журнал: кто, что, когда, откуда, с дифом. Хранится 90
дней.

## Совместимость

Обратной несовместимости нет, кроме двух честных изменений в `preview`-контракте:
`DELETE` отвечает `200 {deleted: true}` вместо пустого `204` (нужно для
идемпотентного повтора), а незнакомые поля в теле теперь дают `422` вместо тихого
отбрасывания. Новые таблицы (`table_meta`, `field_meta`, `system_audit`,
`api_idempotency`) создаются автоматически — обновление сайта не требует ручной
миграции.

## Чего ещё нет

Скоуп-токены (`read` / `content` / `full`) и экран управления токенами: сейчас
токен один, лежит в `system_settings.api_key` и даёт доступ ко всему. Шаблоны
через API и MCP — следующие шаги.

Подробности: [HTTP API](../settings/http-api.md).
