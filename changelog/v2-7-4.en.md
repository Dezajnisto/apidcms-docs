# v2.7.4 — someone else's lead form is gone from the core

**Date:** 23 November 2026
**Type:** patch

## What was wrong

The `views/front/glavnaya.html.twig` template (the ready-made landing page that
ships with the core) had an `iframe` in its "Final Call to Action" block pointing
at a third-party lead-capture form: an address like
`https://crm.<domain>/?entryPoint=leadCaptureForm&id=<id>`. It was the form of the
site the template had originally been written for, and it shipped to everyone who
installs the CMS.

The problem is not the form itself, but that it is somebody else's:

- every site on the CMS showed **an empty box** in that block — the form belonged
  to another domain and did not answer on a new site;
- the address and the form identifier ended up in a public repository, that is in
  code that every user sees and copies.

## What is fixed

The `iframe` block is removed and replaced with a comment in the template: the
core ships no form, build your own in the admin panel (`/admin/forms`) and put it
here, or add a button that leads to your contact page.

**No site changes behaviour.** The core's `glavnaya.html.twig` is a reference for
the AI template generator and for anyone starting from a ready landing page: sites
with their own theme load `themes/<theme>/front/glavnaya.html.twig`, not the core
file.

## How to update

```bash
git pull
```

and redeploy the core to your site. If you already edited that block in your own
theme, nothing to do — the core file does not override your theme.
