## Что нового

### HTTP API (`/api/v1/`)

Ядро получило API для внешних потребителей — мобильных клиентов, скриптов,
интеграций. Авторизация токеном, ответы в JSON, ошибки в едином формате
`{"error": {"code": "...", "message": "..."}}`.

| Метод | Что делает |
|---|---|
| `GET /api/v1/tables` | список таблиц проекта |
| `GET /api/v1/tables/{таблица}` | записи таблицы (пагинация, сортировка) |
| `GET /api/v1/tables/{таблица}/{id}` | одна запись |
| `POST /api/v1/tables/{таблица}` | создать запись |
| `PUT /api/v1/tables/{таблица}/{id}` | обновить запись |
| `DELETE /api/v1/tables/{таблица}/{id}` | удалить запись |
| `GET /api/v1/tables/{таблица}/schema` | схема таблицы |
| `GET /api/v1/articles` | статьи блога |
| `GET /api/v1/articles/{slug}` | одна статья |
| `POST/PUT/DELETE /api/v1/articles/...` | управление статьями |

Подключение — `core/router.php`: запросы с префиксом `api` уходят в `Api\Router`
раньше админки. Системные таблицы (`system_settings`, `users`, `user_tokens`)
через API недоступны — тот же чёрный список, что у AI-помощника.

### Кэш внешнего контента

`ExternalPageLoader::fetchContent()` теперь кэширует содержимое по URL:

- TTL по умолчанию 3600 с, задаётся в конструкторе (`$cacheTtl`);
- если сеть недоступна, отдаётся **просроченный** кэш вместо исключения —
  страница не падает и не ждёт таймаут;
- кэш недействителен для пустого ответа: пустая страница не залипает на час.

Зачем: `timeout` запроса — 15 с, и для страницы, собирающей данные из
недоступного внешнего источника, каждый запрос превращался в 15 секунд
ожидания. С кэшем — миллисекунды.
