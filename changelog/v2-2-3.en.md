# v2.2.3 — Tables and articles API, external content cache

**Date:** November 10, 2026
**Type:** feature

## What's new

### HTTP API (`/api/v1/`)

The core now ships an API for external consumers — mobile clients, scripts,
integrations. Token authorization, JSON responses, unified error format
`{"error": {"code": "...", "message": "..."}}`.

| Method | Purpose |
|---|---|
| `GET /api/v1/tables` | list project tables |
| `GET /api/v1/tables/{table}` | table records (paging, sorting) |
| `GET /api/v1/tables/{table}/{id}` | single record |
| `POST /api/v1/tables/{table}` | create record |
| `PUT /api/v1/tables/{table}/{id}` | update record |
| `DELETE /api/v1/tables/{table}/{id}` | delete record |
| `GET /api/v1/tables/{table}/schema` | table schema |
| `GET /api/v1/articles` | blog articles |
| `GET /api/v1/articles/{slug}` | single article |
| `POST/PUT/DELETE /api/v1/articles/...` | manage articles |

Wired in `core/router.php`: requests prefixed with `api` reach `Api\Router`
before the admin panel. System tables (`system_settings`, `users`,
`user_tokens`) are not exposed — same blacklist as the AI assistant.

### External content cache

`ExternalPageLoader::fetchContent()` now caches content per URL:

- default TTL is 3600 s, configurable via the constructor (`$cacheTtl`);
- when the network is down, the **stale** cache is returned instead of throwing —
  the page neither breaks nor waits for a timeout;
- empty responses are not cached, so a broken fetch does not stick for an hour.

Why: the request `timeout` is 15 s, and any page pulling data from an unreachable
external source cost 15 seconds per request. With the cache it is milliseconds.
