### Защита базы данных от прямого доступа

Обнаружена критическая уязвимость: SQLite-база (`cms.db`) может быть доступна по прямой HTTP-ссылке.

**Архитектура:**
apidcms хранит базу в `/admin/storage/database/cms.db` — под защитой админ-панели. Это правильный путь, закреплённый в ядерном fallback-конфиге (`core_lib/front/config/config.php`). Некоторые проекты использовали ошибочный путь `/storage/database/cms.db` (вне админки) — исправлено.

**Решение — тройная защита в .htaccess:**
1. `RewriteRule \.db$ - [F,L]` — блокировка любых `.db` файлов
2. `RewriteRule ^admin(.*)$ index.php [QSA,L]` — админка через CMS
3. `.db` добавлен в список запрещённых расширений `<Files>`

**Консолидация:**
На всех проектах удалены дубликаты баз (`core_lib/admin/storage/`, `storage/database/`). Теперь на каждом проекте ровно один `cms.db` — под защитой админки.

**Документация:**
Добавлена страница «Безопасность» в раздел Настройки — инструкция по проверке защиты, настройка для nginx, регулярный аудит.
