# v2.8.1 — состояние плагинов больше не пишется в plugin.json

**Дата:** 27 ноября 2026
**Тип:** patch

## Что было

Галочка «Активировать / Деактивировать» на странице плагина переписывала
`plugins/<имя>/plugin.json` — файл, который лежит в git. После каждого
переключения серверная копия расходилась с коммитом.

Само по себе это выглядит безобидно, но у него есть цена: любой деплой, который
проверяет «не правили ли файл в браузере» (сравнивая сервер с последним
коммитом), начинает отказывать. Приходится идти на `--force` — то есть
перезаписывать серверные правки вслепую. На раскатке одного плагина по восьми
сайтам это случилось восемь раз подряд, и каждый раз нужно было вручную
убеждаться, что на сервере нет чужой правки.

## Что исправлено

Состояние «включён/выключен» теперь хранится в
`storage/database/plugins-state.json`:

```json
{ "webchat": true, "cart": false }
```

`"enabled"` в `plugin.json` остаётся значением **по умолчанию** — тем, что
шипится вместе с плагином. Файл состояния его перекрывает, поэтому:

- галочка в админке не меняет ни одного файла в git — деплой перестал отказывать;
- сайт, где плагин выключили, остаётся с выключенным плагином и после деплоя,
  который приносит `"enabled": true` из репозитория;
- удалить файл состояния — значит вернуть все плагины к значениям по умолчанию.

Запись идёт через временный файл и `rename`: обрыв на середине не оставит
половину JSON, из которой «все плагины по умолчанию».

## Почему не в базе данных

Первым побуждением было положить состояние в `plugin_settings`, рядом с
остальными настройками плагинов. Не работает: `bootstrap.php` загружает плагины
**до** подключения к базе. Выключенный плагин успевал выполнить свой `init.php`
по значению из файла — то есть выключение из админки просто не срабатывало.
Проверено на стенде: состояние из базы читается только на втором вызове
`loadPlugins()`, когда `init.php` уже выполнен.

`storage/database/` не уезжает деплоем и попадает в бэкапы вместе с базой, так
что состояние сайта лежит там же, где его данные.

## Как обновиться

```bash
git pull
```

и перезалить ядро на сайт. Миграция не нужна: пока файла состояния нет,
действуют значения из манифестов — ровно то, что было раньше.
