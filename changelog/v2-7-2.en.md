# v2.7.2 — the installer runs again

**Date:** 20 November 2026
**Type:** patch

## What was wrong

The installer (`install.php`) did not run at all. Since version 2.2.2 it
contained a dangling `} else { … }` block with no opening `if`, so PHP died with
`Parse error: unexpected token "else"` before the installation even started.

This was a syntax error, not a logic error: neither the command line
(`php install.php`) nor the web form (`/install.php`) worked. Installing a fresh
copy of the CMS without hand-editing the core was impossible.

## What is fixed

**1. Installer syntax.** The dangling `else` is gone. The installer now runs to
completion: directory structure, `.htaccess`, `custom.css`, theme templates,
configs, database.

**2. The installer wrote its configs to the wrong place.** It treated the web
root (`www/`) as the site root, while `config/`, `storage/`, `themes/` and
`tmp/` live one level above — that is the site root the core actually reads. As a
result it created a second set of directories inside `www/`:

```
www/config/admin.php          ← password "admin", the core never reads it
www/storage/database/cms.db   ← a second database, never read
www/themes/default/front/     ← a second theme, never read
```

The site still worked — on the default config, that is, **with the password
`admin`**. The installer now distinguishes the site root from the web root, so
the password you type into the form lands where the core looks for it.

**3. Site name in the header.** `base.html.twig` used a `site_name` variable that
the frontend never passes (it passes `site_title`). A fresh site showed “My
Site” in the header and “All rights reserved” in the footer instead of the name
from settings. Header and footer now fall back to the configured site title.

## Upgrading

Update the core the usual way. There are no migrations; the database and your
content are untouched.

If you installed with 2.2.2–2.7.1 and **never** changed the admin password by
hand, check it. The password from the install form went into
`www/config/admin.php`, which the core never reads, so login worked with the
default `admin`. Change the password in the admin panel and delete the stray
`www/config`, `www/storage`, `www/themes` directories if they exist.

## Technical details

- `INSTALLER_VERSION` → `1.2.1`
- The installer now has an explicit site root; `config/`, `storage/`, `themes/`
  and `tmp/` are resolved from it
- `base.html.twig`: `{{ site_name|default(site_title) }}`
