# v2.5.0 — an MCP server and an assistant that looks instead of paraphrasing

**Date:** November 16, 2026
**Type:** feature

## Why

2.4.0 made the data understandable and writes safe. But a gap remained between
"the CMS has everything an agent needs" and "an agent can use it": external
clients needed a protocol, and the built-in assistant still received **the whole
documentation (~163 KB, ~55k tokens) plus a table dump in every request**. That
is why it advised rather than acted: to do something it would have had to guess.

## New: an MCP server

`POST /mcp` — a Model Context Protocol server: JSON-RPC 2.0 over Streamable
HTTP, stateless, with the same Bearer token as the API. Cursor, [CC] and any MCP
client connects with one line of config.

**12 tools:** `schema.get`, `records.list/get/create/update/delete`,
`navigation.get`, `relations.list`, `audit.list`, `docs.list/get/search`.

**Resources:** `apidcms://schema`, `apidcms://navigation`, `apidcms://docs/toc`
and `apidcms://docs/{slug}` — the whole documentation as resources, one article
at a time.

This is not a second API: the tools call the same core services as `/api/v1` —
schema, write validation, audit. Every write through MCP lands in the audit log
marked `actor: mcp`, and failures come back as a machine-readable field list
(`column`, `rule`, `got`, `expected`) so the model fixes itself.

## New: an assistant on tools

The built-in assistant in the admin panel now runs on function calling. The
prompt carries only a compact description of what can be asked; it requests the
schema, rows and articles itself.

| | Before | Now |
|---|---|---|
| Documentation in the prompt | all of it, ~163 KB | contents ~10 KB, articles on demand |
| Table dump | always | only if it asks |
| Order of magnitude | ~55k tokens per message | ~3k + 1–2 articles |

And the important part: it now **acts**. "Add three reviews to the reviews table"
is a `records.create` call with field validation, not instructions for doing it
by hand.

Switches: `ai_assistant_tools` (`1` by default, `0` — the old mode) and
`ai_assistant_max_steps` (`6`).

## Fixed

- `init_system_tables.php` could not be run directly: the autoloader looked in
  the wrong directory (`Class "Core\Database" not found`).
- Running it directly created a **second `cms.db`** inside `www/storage/` — the
  project root was computed as the core directory.
- The documentation cache no longer writes inside the core: it moved to
  `storage/cache/docs/` and is cleared with "Clear cache".

## Compatibility

No breaking changes: `/api/v1` is untouched, the old assistant mode is behind a
flag, and MCP is a new path.
