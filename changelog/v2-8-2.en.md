# v2.8.2 — AI context: theme templates, limits, end of the legacy mode

**Date:** 27 November 2026
**Type:** patch

## What was wrong

Three problems in one place — in what travels to the model along with a question.

**1. The template and CSS generators ran with no templates at all.** The code
looked for them in old-structure paths (`www/front/app/views`,
`www/core/views/front`, `www/core_lib/front/app/views`). None of them exists in
the project: the core lives in `www/core/views/front`, the theme in
`themes/<active>/front`. The function silently returned an empty array, so the
model wrote CSS without seeing a single template of the site.

**2. Context limits defaulted to "unlimited".** The shipped values were zeros,
and `0` in the code meant "do not limit". The prompt grew with the site
silently: on one site every request carried 88 KB of `custom.css`.

**3. The legacy assistant mode stayed alive** (`ai_assistant_tools=0`). Measured
on the stand: **222,824 bytes, ~74k tokens** of documentation per request, plus
a table dump and `custom.css`. It was off by default, so its price never caught
anyone's eye — but the code and the setting were there.

## What is fixed

**Templates now come from the active theme**; the core only fills in what the
theme does not have at all. The order matches how Twig renders: `base.html.twig`
first, then the other root-level theme templates alphabetically, then root-level
core templates, then partials from subdirectories.

Before, only names from a hardcoded list were taken (`base`, `page`, `home`,
`blog`…), so on a site with `catalog.html.twig` / `catalog_single.html.twig` —
that is, with its main templates — the model never saw them: those names are not
in the list.

`getCssContext()` also looked for the file at a hardcoded `themes/default/...`;
on a site with a different theme it found nothing. The path now follows the
active theme, and `storage/css/custom.css` (the one the "Design" editor writes)
comes first.

**Limits are on by default:** 20 KB per file, 60 KB for all templates, 20 KB for
CSS. `0` or empty means the built-in limit, `-1` means deliberately unlimited.

**The legacy mode is gone.** `assistantWithDocs()`, `AI::assistant()`,
`DocsFetcher::getKnowledgeBase()` and the `ai_assistant_tools` setting were
removed. The assistant works through tools only — the same layer `/api/v1` uses:
schema and records arrive when the model asks for them, not as a dump.

## What is added

**`Core\AIContext`** — context assembly as a separate class: active theme,
template directories, assembly with limits, and `summary()`. The logic used to
live inside the controller, where a path mistake could not be noticed: it did not
fail, it returned an empty array.

**The settings screen shows how much goes to the model.** The AI tab has a "What
goes to the model now" block: theme, number of templates and their size, CSS size
(flagged when cut by the limit), and the total in bytes and tokens. Prompt size
should not be invisible.

## How to check on your site

1. Settings → AI → "What goes to the model now". The theme and the numbers are
   right there.
2. Open the template editor, press "AI", ask for a change. The generated code
   should use **your** theme's blocks and classes, not the core ones.

## How to update

```bash
git pull
```

and redeploy the core to your site. No migration is needed: the old `0` values in
settings now mean "built-in limit" rather than "no limit".
