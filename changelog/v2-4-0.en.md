# v2.4.0 — an API you can trust with writes

**Date:** November 16, 2026
**Type:** feature

## Why

A CMS today is not only for a human in a browser: content is increasingly edited
by an agent. An agent needs three things — to learn how the project is built, to
understand what the data means, and to be able to write safely. All three landed
in this release.

The real problem was not a lack of endpoints but **silent incompleteness**:
`/api/v1/tables` answered `200 OK` with the shape of the tables, while the
meaning (`price` is rubles, `status` is `active` rather than `published`) and the
page graph stayed out of sight. Writes accepted anything and failed with a `500`
inside the database. The agent built a plan on half the picture and never
noticed. A `404` is cheap: it is visible and leads to a question. A confident
`200` with half the truth is expensive.

## Discovery: what is this site

**`GET /api/v1`** — a public index: CMS, version, `preview` status and a list of
capabilities, each marked `ready` or `planned`. The
`X-apidcms-api: v1-preview` header is on every API response.

**`GET /api/v1/schema`** — the whole project in one payload: tables, columns
(type, `NOT NULL`, default, enums from `CHECK`), metadata, foreign keys,
many-to-many relations and the page graph. One request instead of walking
`/tables` and `/schema` per table.

**`GET /api/v1/navigation`** — `page_config` (`source_table`, `template`,
`filters`, `get_filters`, `items_per_page`, `sort`) comes back resolved instead of
as a raw JSON string. A broken `page_config` does not break the response: the
page is listed with a `page_config_error` field.

**`GET /api/v1/relations`** — many-to-many relations from `entity_relations`.

## Meaning: what PRAGMA cannot know

A table is now described in human terms: label, purpose, description; a column
has a label, note, format, example and the list of allowed values. Edited in the
admin panel: Tables → Structure → **"Semantics"**. Stored in `table_meta` and
`field_meta`, served through the API: the only part of a description that cannot
be recovered from code.

`null` in `/schema` means "not described", not "irrelevant" — values are never
invented.

## Writes: validation instead of junk in the database

**`GET /api/v1/tables/{t}/json-schema`** — JSON Schema of a table (draft
2020-12) with extensions: labels, formats, enums, references to related tables.
An agent validates on its side before sending.

**`POST`/`PUT` are validated** against the column type, `NOT NULL`, defaults,
enums, foreign keys, format (`integer`, `money`, `date`, `url`, `email`, `slug`),
`VARCHAR(n)` length. An unknown field is an error, not a silent drop: a typo in a
field name no longer loses data.

A refusal is `422` with a machine-readable list, so the agent fixes itself:

```json
{"error": {"code": "validation_failed", "action": "insert",
  "fields": [{"column": "price", "rule": "type",
              "got": "1500 RUB", "expected": "integer (INTEGER)"}]}}
```

**`?dry_run=1`** on `POST`/`PUT`/`DELETE` — what would change and which pages
show it (`affected_urls` from `page_config`), nothing is stored.

**`Idempotency-Key`** — repeating a request returns the first response and does
not create a second row. Agents retry; three identical news items in production
are a matter of time.

**`GET /api/v1/audit`** — the log: who, what, when, from where, with a diff. Kept
for 90 days.

## Compatibility

No breaking changes, apart from two honest shifts in the `preview` contract:
`DELETE` answers `200 {deleted: true}` instead of an empty `204` (needed for
idempotent retries), and unknown fields in a body now produce `422` instead of
being silently dropped. New tables (`table_meta`, `field_meta`, `system_audit`,
`api_idempotency`) are created automatically — upgrading a site needs no manual
migration.

## Not there yet

Scope tokens (`read` / `content` / `full`) and a token screen: today there is one
token in `system_settings.api_key` that grants access to everything. Templates
through the API and MCP are the next steps.
