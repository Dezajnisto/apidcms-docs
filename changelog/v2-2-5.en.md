# v2.2.5 — Template editor shows the reason instead of "404"

**Date:** November 10, 2026
**Type:** fix

## Fixed

**Saving a template in the admin panel showed "404 Page not found"** instead of
the real reason. `TemplateController` caught every exception (including a failed
file write) and rendered `error/404`, so the admin saw "404" on a page that
exists and looked for a routing problem instead of a permissions problem.

What changed:

- errors are split into two classes: "not found" (a real 404) and "could not
  write" — the latter renders the new `error/action.html.twig` page with the
  error text and a permissions hint;
- `saveTemplate()` writes the real reason to `error_log`: file owner,
  `is_writable()` for the file and for the directory;
- a failed pre-save backup no longer blocks the save itself — a warning goes to
  the log and the template is written.

## The usual cause of a failed write

`themes/` belongs to `admin:www-data` with `750/640`, while php-fpm runs as
`www-data`: it can read but not write. The templates directory must be
group-writable for `www-data`:

```bash
# files 660, directories 2770 (setgid — new files inherit the group)
sudo chown -R admin:www-data themes
sudo chmod -R u=rwX,g=rwX,o= themes
sudo find themes -type d -exec chmod 2770 {} +
```

`www/`, `config/` and `bin/` stay read-only — that is the backdoor protection and
it should not be relaxed.
