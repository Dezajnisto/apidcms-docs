# v2.2.5 — Редактор шаблонов: причина вместо «404»

**Дата:** 10 ноября 2026
**Тип:** fix

## Исправлено

**Сохранение шаблона в админке показывало «404 Страница не найдена»** вместо
настоящей причины. `TemplateController` ловил любое исключение (включая отказ
записи файла) и рендерил `error/404` — админ видел «404» на странице, которая
существует, и искал проблему в маршрутах, а не в правах.

Что изменилось:

- ошибки разделены на два класса: «не найдено» (настоящий 404) и «не удалось
  записать» — для второго новая страница `error/action.html.twig` с заголовком,
  текстом ошибки и подсказкой про права;
- `saveTemplate()` пишет в `error_log` реальную причину: владельца файла,
  `is_writable()` для файла и для каталога;
- неудачный бэкап перед сохранением больше не мешает записи самого шаблона —
  в лог уходит предупреждение, шаблон сохраняется.

## Причина отказа записи (частый случай)

`themes/` принадлежит `admin:www-data` с правами `750/640`, а php-fpm работает
под `www-data`: читать может, писать — нет. Нужно, чтобы каталог шаблонов был
доступен группе `www-data` на запись:

```bash
# файлы 660, каталоги 2770 (setgid — новые файлы наследуют группу)
sudo chown -R admin:www-data themes
sudo chmod -R u=rwX,g=rwX,o= themes
sudo find themes -type d -exec chmod 2770 {} +
```

`www/`, `config/` и `bin/` при этом остаются только для чтения — это защита от
бэкдора, менять её не нужно.
