# v2.5.1 — DEFAULT в схеме: значение, а не текст SQL

**Дата:** 16 ноября 2026
**Тип:** fix

## Что было не так

`PRAGMA table_info` отдаёт значение по умолчанию не как значение, а как **текст
SQL**: у строковой колонки кавычки остаются внутри — `'active'`, `"active"`,
`` `active` ``, `[active]`.

Из этого выходили две проблемы:

1. **В JSON Schema уезжали кавычки.** `GET /api/v1/tables/{таблица}/json-schema`
   и `schema.get` в MCP показывали `"default": "'active'"`. Агент читает схему,
   чтобы понять, что можно не передавать, — и, доверяя ей, записал бы в базу
   значение **вместе с кавычками**.
2. **Удаление колонки портило дефолт.** SQLite не умеет `DROP COLUMN`, поэтому
   таблица пересобирается: старый текст дефолта подставлялся в новое
   определение ещё раз закавыченным, и получалось `DEFAULT '''active'''`.

Нашлось сразу после раскатки 2.5.0 на bajto.ru — на первом же запросе схемы
живой таблицы `catalog`.

## Что сделано

`Core\Database::normalizeDefault()` — одна общая нормализация для схемы и для
пересборки таблицы:

- строковый литерал разворачивается в значение (все четыре вида кавычек, включая
  удвоенную кавычку внутри);
- выражения (`CURRENT_TIMESTAMP`, `NULL`) и числа остаются как есть.

`SchemaInspector` использует её при построении схемы, `deleteColumn()` — при
создании новой таблицы (числа теперь пишутся без квотирования).

## Как проверить

```
GET /api/v1/tables/pages/json-schema
→ "status": { "type": "string", "default": "active" }
```

Было: `"default": "'active'"`.

## Совместимость

Ломающих изменений нет. Меняется только то, что агент видит в схеме, — и
меняется в сторону правды.
