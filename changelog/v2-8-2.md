# v2.8.2 — AI-контекст: шаблоны темы, лимиты, конец legacy-режима

**Дата:** 27 ноября 2026
**Тип:** patch

## Что было

Три проблемы в одном месте — в том, что уходит в модель вместе с вопросом.

**1. Генератор шаблонов и CSS работал вообще без шаблонов.** Код искал их в
путях старой структуры (`www/front/app/views`, `www/core/views/front`,
`www/core_lib/front/app/views`). Ни одного из них в проекте нет: ядро лежит в
`www/core/views/front`, тема — в `themes/<active>/front`. Функция молча
возвращала пустой массив, и модель писала CSS, не видя ни одного шаблона сайта.

**2. Лимиты контекста по умолчанию были «без ограничения».** В поставке стояли
нули, а `0` в коде означало «не ограничивать». Промпт рос вместе с сайтом
незаметно: на одном из сайтов в каждый запрос уходило 88 КБ `custom.css`.

**3. Живым оставался legacy-режим ассистента** (`ai_assistant_tools=0`). Замер
на стенде: **222 824 байта, ~74k токенов** документации в каждый запрос, плюс
дамп таблиц и `custom.css`. По умолчанию он был выключен, поэтому цена никому
не бросалась в глаза — но код и настройка были на месте.

## Что исправлено

**Шаблоны берутся из активной темы**, ядро — только добор того, чего в теме нет
вовсе. Порядок как у Twig при рендере: `base.html.twig` первым, затем остальные
корневые шаблоны темы по алфавиту, затем корневые шаблоны ядра, затем партиалы
из подкаталогов.

Раньше брались только имена из жёсткого списка (`base`, `page`, `home`, `blog`…),
и на сайте с `catalog.html.twig` / `catalog_single.html.twig` — то есть с
главными шаблонами — модель их не видела: таких имён в списке нет.

`getCssContext()` тоже искал файл по захардкоженному `themes/default/...`; на
сайте с другой темой он не находился. Теперь путь строится по активной теме, а
`storage/css/custom.css` (тот, что правит редактор «Дизайн») идёт первым.

**Лимиты включены по умолчанию:** 20 КБ на файл, 60 КБ на все шаблоны, 20 КБ на
CSS. `0` или пусто — встроенный лимит, `-1` — осознанно без ограничения.

**Legacy-режим удалён.** Убраны `assistantWithDocs()`, `AI::assistant()`,
`DocsFetcher::getKnowledgeBase()` и настройка `ai_assistant_tools`. Ассистент
работает только через инструменты — то есть через ту же прослойку, что `/api/v1`:
схема и записи приходят по запросу модели, а не дампом.

## Что добавлено

**`Core\AIContext`** — сборка контекста отдельным классом: активная тема,
каталоги шаблонов, сборка с лимитами и `summary()`. Раньше логика жила внутри
контроллера, и ошибку в путях нечем было заметить — она не падала, а отдавала
пустой массив.

**Экран настроек показывает, сколько уходит в модель.** Во вкладке AI появился
блок «Сейчас уходит в модель»: тема, число шаблонов и их объём, размер CSS
(с пометкой «обрезано лимитом») и итог в байтах и токенах. Объём промпта не
должен быть невидимым.

## Как проверить у себя

1. Настройки → AI → «Сейчас уходит в модель». Там видно тему и цифры.
2. Открыть редактор шаблона, нажать «AI», попросить что-нибудь поправить.
   Сгенерированный код должен использовать блоки и классы **вашей** темы, а не
   ядровой.

## Как обновиться

```bash
git pull
```

и перезалить ядро на сайт. Миграция не нужна: старые значения `0` в настройках
теперь означают «встроенный лимит», а не «без ограничения».
