# 📚 База знаний AI — как ассистент читает документацию

Начиная с версии **2.5.0** AI-ассистент в админке **не загружает весь справочник
в каждый запрос**. Он получает в промпте компактное оглавление возможностей и
сам решает, какую статью или таблицу ему открыть.

Изменилось не только потребление токенов, но и поведение: раньше ассистент
мог только советовать, теперь у него есть инструменты — он смотрит реальную
схему, реальные записи и может их изменить.

---

## 🧠 Как это работает

У ассистента есть набор инструментов (`Core\AgentTools`), те же, что отдаёт
[MCP-сервер](../settings/mcp.md):

| Инструмент | Что отдаёт |
|---|---|
| `schema.get` | таблицы, колонки, допустимые значения, связи, карта страниц |
| `records.list` / `records.get` | реальные записи таблицы |
| `records.create` / `update` / `delete` | изменение данных с проверкой полей |
| `navigation.get` | какая таблица питает какой URL каким шаблоном |
| `docs.list` / `docs.get` / `docs.search` | документация: оглавление, одна статья, поиск |

Цикл ответа:

1. Пользователь задаёт вопрос.
2. Модель решает, чего ей не хватает, и вызывает инструмент
   (`docs.search` → `docs.get` для вопроса про CMS, `schema.get` для вопроса
   про данные сайта).
3. Результат возвращается модели одним сообщением (`role: tool`).
4. Модель отвечает. Обычно это 1–3 шага.

Предел шагов — настройка `ai_assistant_max_steps` (по умолчанию 6), каждый
результат обрезается до 16 КБ, чтобы одна большая таблица не заняла весь
контекст.

## 📉 Сколько это стоит

| Что | Было (до 2.5.0) | Стало |
|---|---|---|
| Документация в промпте | весь справочник: ~163 КБ текста | оглавление: ~10 КБ, статьи — по запросу |
| Дамп таблиц сайта | всегда | только если модель спросит |
| Порядок | ~55–60k токенов **на каждое сообщение** | ~3k в первом запросе + 1–2 статьи по ~1k |

Вопрос «как настроить кэширование» теперь стоит один поиск по оглавлению и одну
статью, а не весь справочник. Вопрос про данные сайта стоит одного `schema.get`
и не стоит ничего, если модель уже его вызывала.

## 🗄️ Технические детали

### `Core\DocIndex` — оглавление и одна статья

```php
$index = new \Core\DocIndex();
$toc = $index->toc();               // slug, title, section, description
$doc = $index->get('http-api');     // одна статья, без front-matter
$hits = $index->searchDeep('кэш');  // поиск: сначала заголовки, потом текст
```

### `Core\DocsFetcher` — загрузка и кэш

```php
$fetcher = new \Core\DocsFetcher();
$manifest = $fetcher->getManifest();          // манифест
$content  = $fetcher->getDocContent($url);    // одна статья
```

| Данные | TTL | Расположение |
|---|---|---|
| manifest.json | 1 час | `storage/cache/docs/manifest.json` |
| Статьи (.md) | 6 часов | `storage/cache/docs/<md5-хеш>.md` |

Кэш живёт в `storage/` проекта, а не внутри ядра: раньше он складывался в
`core/admin/storage/docs_cache` и переживал обновления ядра как мусор. Чистится
кнопкой «Очистить кэш» в админке.

Источник — `raw.githubusercontent.com/Dezajnisto/apidcms-docs` (ветка `master`,
язык берётся из настройки `admin_language`). Если GitHub недоступен,
используется просроченный кэш; если кэша нет — ассистент работает без
документации, но с инструментами по данным сайта.

## ⚙️ Настройки

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `ai_assistant_tools` | `1` | `0` — вернуть старый режим: весь справочник и дамп таблиц в системный промпт |
| `ai_assistant_max_steps` | `6` | сколько раундов вызова инструментов допустимо (1–10) |

Обе настройки правятся в админке: Настройки → AI.

## 🔮 Дальнейшие планы

- инвалидация кэша документации отдельной кнопкой (сейчас — общая «Очистить кэш»);
- локальное зеркало документации для проектов без доступа к GitHub;
- инструменты для шаблонов (`templates.read/write`), чтобы ассистент доводил
  задачу до конца, а не останавливался на данных.
