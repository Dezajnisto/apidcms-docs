# Мультиязычные сайты

apidcms поддерживает опциональную мультиязычность фронтенда. По умолчанию она **выключена** — сайт работает как обычно. Дополнительные языки включаются только когда нужны.

## Как это работает

Базовый язык всегда без префикса, дополнительные — с префиксом в URL:

- `https://mysite.ru/` — базовый язык (обычно русский)
- `https://mysite.ru/en/` — дополнительный язык

При заходе на `/en/...` ставится кука `site_lang` (на год). При возврате на базовый язык (`/...`) кука удаляется. Кука **не вызывает** автоматический редирект — язык управляется исключительно URL.

## Настройки

Два ключа в `system_settings`:

| Настройка | По умолчанию | Описание |
|---|---|---|
| `site_language` | `ru` | Базовый язык фронтенда |
| `site_languages` | `null` | JSON-массив доп. языков. `null` = мультиязычность выключена |

## Включение дополнительного языка

Через админку: Настройки → Системные, либо напрямую в БД:

```sql
UPDATE system_settings SET setting_value = '["en"]'
WHERE setting_key = 'site_languages';
```

После этого:

- `/en/page` — английская версия любой страницы
- Переключатель RU/EN в хедере (только при непустом `site_languages`)
- Кука `site_lang` запоминает выбор языка

### Как работает переключатель

Переключатель сохраняет текущую страницу при смене языка:

- На `/en/docs` → RU ведёт на `/docs`, EN на `/en/docs`
- На `/` → RU ведёт на `/`, EN на `/en/`

Это достигается через переменную `current_path` (путь без языкового префикса), которая автоматически передаётся в шаблоны.

## Перевод шаблонов

Статические строки (навигация, кнопки, заголовки) — через объект `_t` в `base.html.twig`:

```twig
{% set _t = {
  ru: {
    home: "Главная",
    docs: "Документация",
    search: "Поиск"
  },
  en: {
    home: "Home",
    docs: "Documentation",
    search: "Search"
  }
} %}

<html lang="{{ site_lang }}">
...
<a href="{{ url('/') }}">{{ _t[site_lang].home }}</a>
<input placeholder="{{ _t[site_lang].search }}">
```

### Важно: используйте url() для всех внутренних ссылок

Функция `url()` автоматически добавляет языковой префикс к страницам (но не к ассетам):

```twig
{# Правильно — префикс добавится автоматически #}
<a href="{{ url('/docs') }}">{{ _t[site_lang].docs }}</a>

{# Неправильно — ссылка всегда без префикса #}
<a href="/docs">{{ _t[site_lang].docs }}</a>
```

На EN-странице `url('/docs')` вернёт `/en/docs`, на RU — `/docs`. Ассеты (`/storage/...`, `/admin/...`) префикс не получают.

### Переключатель языков

```twig
{% if get_setting('site_languages')|default('') is not empty %}
<div class="lang-switch">
    <a href="/{{ current_path }}"
       class="lang-link{% if site_lang == 'ru' %} active{% endif %}">RU</a>
    <a href="/en/{{ current_path }}"
       class="lang-link{% if site_lang == 'en' %} active{% endif %}">EN</a>
</div>
{% endif %}
```

Переменные в шаблонах:
- `site_lang` — текущий язык (`ru`/`en`)
- `current_path` — путь страницы без префикса (на `/en/docs` → `docs`)

### Добавление перевода на новую страницу

1. Добавьте ключи в `_t` (секции `ru` и `en`) в `base.html.twig`
2. В шаблоне используйте `{{ _t[site_lang].ваш_ключ }}`
3. Все внутренние ссылки — через `{{ url('/путь') }}`
4. Готово

## Core\I18n — программный доступ

```php
use Core\I18n;

// Разрезолвить одно значение
$title = I18n::resolve($row['title'], 'en');
// "Привет" → "Привет" (plain text)
// '{"ru":"Привет","en":"Hello"}' → "Hello"

// Разрезолвить массив
$items = I18n::resolveArray($items,
    ['title', 'description', 'content'], 'en');

// Создать JSON для хранения
$json = I18n::encode(
    ['ru' => 'Привет', 'en' => 'Hello'], 'ru');
// → '{"ru":"Привет","en":"Hello"}'
// Если только базовый язык → plain text "Привет"

// SQL для поиска по локали
$expr = I18n::searchExpr('title', ['ru', 'en']);
// → COALESCE(json_extract(title, r'$.ru'),
//            json_extract(title, r'$.en'), title)
```

## Внешние страницы: content_url_{locale}

Для внешних страниц (плагины, документация) есть поддержка локализованных URL контента:

```json
{
  "content_url": "https://...account/README.md",
  "content_url_en": "https://...account/README.en.md"
}
```

`handleExternalPage()` автоматически выбирает `content_url_en` для английской локали, `content_url_de` для немецкой и т.д. Это позволяет хранить переводы контента в отдельных файлах без изменения кода.

## JSON-формат для контента

Контент (страницы, посты) может храниться в JSON:

```sql
-- Один язык
title = "Главная страница"

-- Несколько языков
title = '{"ru":"Главная","en":"Home page"}'
```

`FrontController::render()` автоматически резолвит поля `title`, `description`, `content` через `resolveI18nData()`. Шаблоны получают готовые строки.

## Поиск

Поиск работает через `LIKE` по текстовым полям. Для JSON-полей находит ключи вместе со значениями (небольшой шум). В будущем — `json_extract()` для чистого поиска по локали.

## Ограничения

- **Контент** (страницы, посты) пока на одном языке. JSON для контента — следующий этап.
- **Accept-Language** автоопределение не реализовано.
- **Админка** всегда на `admin_language`, независимо от фронтенда.
